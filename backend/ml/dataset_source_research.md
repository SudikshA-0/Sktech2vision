# Alternative image sources for Sketch2Vision

**Research date:** 2026-11-01  
**Purpose:** identify lawful, practical source images for a small Pix2Pix edge-map/photo experiment. This is a source assessment, not legal advice or permission to acquire, train on, redistribute, or publish any record.

## Project fit and decision criteria

The current preparation pipeline accepts local JPG/JPEG/PNG files, splits source images before deriving Canny edges, and saves each edge map alongside the matching RGB target. `--source-metadata-csv` can map source provenance into the prepared records. The default preprocessing size is 256×256; the documented Pix2Pix baseline uses 128×128. Use the existing deterministic source-level split and identical geometry for each edge/target pair.

This creates **synthetic edge-map/photo pairs** from the same photographs. They are aligned pairs, but they are not human sketch/photo pairs. Success on these pairs would not establish that the model generalizes to freehand user sketches.

For this review, “commercial use” and “derivatives” describe the stated rights instrument only. Rights in depicted people, trademarks, donor restrictions, cultural sensitivity, and source-site terms may still apply. A provider’s dataset-level or metadata license is not automatically the license of its image files. All records must remain `pending_manual_review` until their specific evidence has been reviewed.

## License interpretation for filtering

- **CC0:** waiver/public-domain dedication for copyright rights the releasor controls; generally supports commercial reuse and derivatives without attribution conditions. Preserve source/creator anyway. Check third-party/personality/privacy and other non-copyright rights.
- **Public Domain Mark (PDM):** a status mark for works believed to be free of known copyright restrictions, not a license grant. Confirm the item’s provenance, jurisdictional basis, and any other rights; do not treat the string “public domain” as sufficient proof.
- **CC BY:** commercial reuse and adaptations are permitted if license conditions, including attribution, license link, change notices, and other required notices, are followed.
- **CC BY-SA:** commercial reuse and adaptations are permitted with attribution; adaptations shared must use the same or compatible license. Review whether distributing the derived edge map, paired dataset, or model artifacts triggers conditions before release.
- **CC BY-NC / other non-commercial terms:** not suitable if commercial use must be allowed. NC restrictions also make public release or downstream use more constrained.
- **ND / no-derivatives terms:** unsuitable for creating and distributing transformed edge-map derivatives without permission. Training implications may need specialist review, but do not treat these as a clear derivative permission.
- **Rights statements such as “No known copyright restrictions”:** evidence/status statements, not necessarily a license. Keep unresolved until authoritative item evidence is obtained.

Europeana documents that its open set comprises PDM, CC0, CC BY and CC BY-SA, while limited/restricted rights include non-commercial and no-derivatives options. Its rights guidance also warns that rights statements are supplied by data providers and should accurately reflect the object. Smithsonian explicitly limits CC0 to rights it can waive and warns third-party rights can still apply. These qualifications prevent automatic approval.

## Source evidence and verified details

### Smithsonian Open Access — recommended first feasibility query

- **Official source:** [Smithsonian Open Access](https://www.si.edu/openaccess), [FAQ](https://www.si.edu/openaccess/faq), [Terms of Use](https://www.si.edu/termsofuse), [NMNH data access](https://naturalhistory.si.edu/research/idsc/data-access).
- **License evidence:** The FAQ says CC0-designated assets may be used, transformed, shared, including commercially, without Smithsonian permission or attribution; third-party rights remain the user’s responsibility. It states that non-CC0 “Usage Conditions Apply” content is restricted and not commercially usable without written permission.
- **Attribution:** not required for CC0 assets by Smithsonian, but it recommends a minimal credit containing title, author, source, license and source URL. Keep this metadata regardless.
- **Acquisition:** official API is hosted via api.data.gov and requires an API key. The FAQ says the API record can include a corresponding image URL for eligible public-domain media. Official collection data is also published on GitHub with weekly refresh. A metadata-only query can filter CC0, image availability and terms before any file fetch.
- **Limitations:** broad institutional collections are not an object-photo benchmark; an item may depict an artifact/specimen rather than a natural scene, and people can trigger publicity/privacy concerns. The 5.2M+ figure includes mixed 2D/3D items, not 5.2M photographs or category-ready records. No per-category counts are asserted here.

### Europeana — recommended second source / fallback

- **Official source:** [Europeana research and collections](https://www.europeana.eu/en/research), [Search API docs](https://europeana.atlassian.net/wiki/spaces/EF/pages/2385739812), [API FAQ](https://europeana.atlassian.net/wiki/spaces/EF/pages/2360508417/Europeana+API+FAQ), [key registration](https://www.europeana.eu/en/how-to-register-for-and-manage-an-api-key), [bulk media guidance](https://pro.europeana.eu/index.php/post/bulk-downloading-media-and-metadata-using-the-europeana-api).
- **License evidence:** Search API supports `reusability=open` (PDM, CC0, CC BY, CC BY-SA), `media=true` for records with a resolvable full-media URL, and metadata filters for image technical properties. The actual media is governed by each record’s `edm:rights`; Europeana API metadata itself is CC0 and does not confer rights in linked partner media.
- **Attribution:** required for CC BY and CC BY-SA; follow each license’s exact terms and the provider’s credit line. Record title, creator, institution, source record URL, rights URI, attribution statement, and change note. CC0/PDM may not require copyright attribution, but retain provenance.
- **Acquisition:** Search API with account/API key, narrow category queries, `reusability=open`, `media=true`, image type and resolution filters; use cursor pagination and retrieve item records. Save candidate metadata first; fetch images only after manual review.
- **Limitations:** multilingual/inconsistent subject metadata; cultural heritage imagery may be paintings, scans, objects or historic scenes. Europeana notes that data providers supply rights statements, so verify statements against provider landing pages and source-level terms. Its collection is over 60M mixed records, not all images. No eligible category counts are asserted.

### Library of Congress — conditional reserve

- **Official source:** [LoC APIs](https://www.loc.gov/apis/), [JSON/YAML API](https://www.loc.gov/apis/json-and-yaml), [PPOC API](https://www.loc.gov/pictures/api), [IIIF image services](https://www.loc.gov/apis/micro-services/image-services/), [copyright guidance](https://www.loc.gov/legal/security-copyright-and-privacy/understanding-copyright/), [P&P rights risk guidance](https://wwws.loc.gov/rr/print/195_copr.html).
- **License evidence:** LoC advises users to inspect item rights statements; “no known restrictions” means no evidence of restrictions was found, not proof that an image is public domain. No general license guarantees commercial/derivative permissions for the catalog.
- **Attribution:** follow item-specific terms and retain citation/source data; no one blanket attribution rule establishes rights. Credit is good provenance practice.
- **Acquisition:** API/JSON and IIIF/file links support metadata search and programmatic retrieval. The main loc.gov API documentation warns that some subsites, including Prints & Photographs, are served by separate interfaces; use the PPOC interface for that catalog.
- **Limitations:** rights review is per image or collection and may require donor/source research. Category counts and resolution distributions are unknown. Do not treat access to a downloadable large JPEG/TIFF as permission to reuse it.

### MS COCO 2017 — benchmark-only, not recommended for acquisition

- **Official source:** [COCO dataset](https://cocodataset.org/), [terms of use](https://github.com/cocodataset/cocodataset.github.io/blob/master/dataset/termsofuse.htm).
- **License evidence:** COCO’s site and annotations are CC BY 4.0, but its terms expressly state that the consortium does not own image copyrights and image users must follow Flickr terms. Thus image commercial/derivative permissions and attribution vary by underlying image/license; annotation CC BY cannot be used as image clearance.
- **Coverage/size:** 118,287 train and 5,000 validation images, variable resolution; full train/val download is roughly 18 GB/1 GB per project’s existing documentation. Standard object classes match seven requested categories (person, dog, cat, car, bicycle, chair, bird). Potted plant is not the same category as flower/tree, and building is not an object label.
- **Acquisition and risks:** official archives are direct, but usually downloaded as full split archives. Selective per-image fetching is technically possible from IDs/URLs, yet it inherits the project’s already observed Flickr 403/429 access and license/source mismatch risks. Not recommended as the first 300-image source.

### NARA and iNaturalist — not recommended as primary sources

- **NARA:** [official API terms](https://www.archives.gov/research/catalog/help/api) provide a searchable metadata/image API with API key and a default quota. NARA forbids using the API to download the entire catalog, directs bulk access to AWS, requires an API non-endorsement notice, and says API content must not be cached or stored. NARA does not provide a blanket image license. That storage restriction conflicts with this project’s normal provenance/pair workflow; seek written clarification before using the API for a retained training corpus. No category counts are known.
- **iNaturalist:** [developer guidance](https://www.inaturalist.org/pages/developers) says the API supports applications, not bulk scraping, recommends around one request per second, and describes a 675,000-photo/5,089-species FGVC 2017 collection. [Media licensing guidance](https://help.inaturalist.org/en/support/solutions/articles/151000169918-can-i-use-the-photos-and-sounds-that-are-posted-on-inaturalist-) says media belongs to contributors and is CC BY-NC by default; individual media can have different licenses. This is only a potential source for dog/cat/bird/flower/tree and does not cover the full target set. Do not harvest individual social-network pages as a shortcut.

## Recommendation and acquisition plan

**Recommended order:**

1. **Run a metadata-only Smithsonian feasibility query first.** Search for a varied set of terms for all ten categories and require (a) a media URL, (b) an explicit CC0/open-access designation on the item record, (c) image dimensions if supplied, and (d) a source/creator record. Save 40–60 candidates per category where possible, with raw rights/provenance fields. Treat this as a feasibility manifest only. Smithsonian is the clearest rights route when the exact media is marked CC0, but its category counts and suitability as photographs are not yet known.
2. **Run a metadata-only Europeana query as a fallback and gap-filler.** Filter `reusability=open`, `media=true`, and image records; preserve exact `edm:rights`, provider, original landing-page, creator, attribution, image URL, dimensions and file size. Prefer CC0/PDM for lower attribution burden; consider CC BY/CC BY-SA only after per-record review and a decision about compliance for redistributed pairs/weights. Do not infer rights from the `open` filter alone.
3. **Build a 300-source review set, not an automatic download set.** Aim for 30 distinct images per category after deduplication and relevance screening, using 30 per category across one source where enough quality candidates exist or a documented mix of the two sources. A candidate can appear in only one primary category for split balancing, while retaining all matching subject tags. Track exact license evidence, creator, source page, dimensions, file size and review notes. Keep all statuses pending until a human verifies the item page, media relation, rights statement, creator/attribution, and any depicted-person or third-party rights concerns.
4. **Confirm storage before any image retrieval.** Current source records do not establish a reliable aggregate byte estimate for a future 300-item selection. Do not derive download size from image dimensions alone. Sum trustworthy per-file byte-size metadata when available; otherwise download a small, separately authorized sample only after review. At 128×128, 300 paired edge/RGB outputs contain about 18.75 MiB of uncompressed pixel data (8-bit one-channel edge plus 8-bit three-channel target), before PNG/JPEG compression and metadata; this is not an estimate of source-image download size.
5. **Only after review, acquire into a new isolated source directory.** Do not overwrite the existing Open Images or Commons manifests, and do not fetch unreviewed candidates. Keep downloaded source files out of Git. Pass the approved provenance CSV to the existing `prepare_dataset.py --source-metadata-csv` path, retain per-source mapping in `splits.json`, then run the strict training dataset validator. This workflow does not change the pipeline or approve licensing by itself.

### What remains unknown / blockers

- No metadata-only queries have yet established 30 relevant, rights-eligible photographs in every category from Smithsonian or Europeana.
- Actual file sizes, dimensions and direct-link reliability must be collected for shortlisted records; corpus-wide totals cannot be converted into a 300-image download estimate.
- Smithsonian CC0 does not resolve third-party rights (especially identifiable people, trademarks, cultural sensitivity or donor restrictions).
- Europeana provider rights labels may need confirmation at the provider page; CC BY-SA compliance and model/artifact redistribution need a project decision.
- Commercial/release plans matter. Academic training and public release of source files, derived edge maps, checkpoints or model weights are distinct uses requiring rights review.
- No source has been approved for acquisition by this document. Existing Open Images and Commons candidates remain unapproved and their pending statuses must remain unchanged.
